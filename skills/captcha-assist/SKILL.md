# CAPTCHA: видимое задание → проверенное продолжение

Применяй к конкретному сайту и текущему поручению. Запрос пользователя решить CAPTCHA этого сайта уже даёт нужное разрешение; не проси его повторно. Обычный запрос прочитать сайт сам по себе не означает согласие на любые действия с аккаунтом: следуй текущим правилам браузерного инструмента. CAPTCHA, вход, 2FA, проверка возраста, оплата и защитная страница браузера — разные ситуации.

## Разобрать блокер

1. Сохрани исходный URL страницы, ожидаемый товар/SKU, вкладку и этап работы в приватный checkpoint. Используй `scripts/challenge.js`: прочитай исходник и загрузи в инициализированный CUA REPL. Скрипт читает только видимый DOM и метаданные, не cookies, токены или скрытое состояние.
2. После HTTP CAPTCHA останови сетевые повторы и открой обычную страницу в разрешённом браузере. Не копируй технический challenge-URL в чат: он может содержать токены. Если вкладка уже открыта, продолжай в ней. Таймаут навигации не требует немедленной перезагрузки — сначала осмотри текущую страницу.
3. Прочитай актуальный DOM/AX. Для визуального задания сделай скриншот. Если проверка в iframe, используй наблюдённый frame locator и документированные API. Пустая страница по адресу проверки означает `challenge_not_loaded`, а не неудачно решённую головоломку; HTTP 403/429 без задания — другой блокер.

```js
var checkpoint = CaptchaAssist.begin({
  target_url: 'URL_ИСХОДНОЙ_СТРАНИЦЫ', browser_id: 'РЕАЛЬНЫЙ_ID',
  tab_id: 'РЕАЛЬНЫЙ_ID', operation_id: 'ID_ТЕКУЩЕЙ_ОПЕРАЦИИ'
});
var challenge = await CaptchaAssist.inspect(tab);
nodeRepl.write(challenge);
```

Сохрани возвращённый checkpoint файловым инструментом до действия. В нём нет содержимого сессии; держи его в `<run>`, не в устанавливаемом скилле. `inspect` — диагностическая подсказка, не замена чтению задания: распознавание текста не покрывает все варианты CAPTCHA.

## Решить через видимый интерфейс

Используй только реально доступные и документированные браузерные действия. Не придумывай координаты, локаторы или метод перетаскивания.

- Checkbox: прочитай текст, выбери единственный наблюдаемый элемент проверки и нажми/отметь его. Затем проверь, появилось ли дополнительное задание.
- Текстовая CAPTCHA: прочитай символы по изображению, введи ответ в наблюдаемое поле CAPTCHA и нажми соответствующую кнопку. Не путай это поле с паролем или кодом 2FA.
- Выбор картинок: прочитай условие, визуально определи нужные фрагменты и выбери их по свежему DOM/скриншоту. При обновлении картинок снова осмотри изменившуюся сетку, не используй старую нумерацию.
- Слайдер/пазл: найди видимый ползунок и цель. Перемещай только если текущий инструмент документирует подходящее действие. `evaluate` используется только для чтения; не синтезируй события, не меняй DOM и не вызывай внутренние обработчики для имитации решения.

Перед отправкой решения вызови `CaptchaAssist.reserveAttempt(checkpoint, challenge)` и сохрани новое состояние. По умолчанию предел — две попытки на блокировку, без циклических перезагрузок. Этот предел относится к отправке решения, а не к отдельным кликам внутри одной сетки. При неопределённом результате сначала осмотри страницу.

Не добывай/не подделывай challenge-токены, не заменяй ответы API, не меняй fingerprint/IP для обхода проверки. Внешние сервисы решения и передача им данных не входят в этот скилл. Здесь агент решает доступное задание в обычном интерфейсе.

## Проверить и продолжить

Исчезновение CAPTCHA само по себе не доказывает успех. Проверь возвращение к ожидаемой странице и появление содержимого, ради которого выполнялась проверка:

```js
// readyLocator строится по наблюдённому DOM: например, заголовок нужной карточки.
var result = await CaptchaAssist.verify(tab, checkpoint, readyLocator);
nodeRepl.write(result);
```

`resumed` означает, что в этой вкладке видна нужная страница. Это не доказывает авторизацию аккаунта или доступ того же curl-клиента: проверь их отдельно. Не экспортируй новую сессию без соответствующего разрешения. В AliExpress после восстановления доступа перечитай SKU, цену, выбор опций и доставку. Не повторяй добавление в корзину автоматически: возобновляй тот же operation_id/run_id и сначала сверяй корзину.

Если задание не загрузилось, не читается, требует неподдерживаемого действия или две попытки исчерпаны, сохрани checkpoint, покажи пользователю конкретную вкладку и назови фактический блокер. При необходимости попроси пройти проверку вручную, сохрани вкладку через документированный `markHandoff`, а после ответа проверь результат. Это ограничение доступного интерфейса, а не успешное автоматическое решение. Не обещай, что прохождение в Firefox автоматически перенесётся во встроенный браузер или curl.

Проверка помощника: `node scripts/test_challenge.cjs`. Это моделируемые состояния; отдельно сообщай, решена ли реальная CAPTCHA на сайте.
